## Strict records and persisted snapshots close the prior High paths

`build_authorization_context` accepts counts only when `type(value) is int`, rejects booleans, strings, fractional and negative counts, and requires finite non-negative monetary values. It also cross-checks segment identity, transaction count, calculation method, and monetary fields against stored deterministic impact evidence. Malformed records therefore make the authorization basis invalid and force grounding and confidence to zero.

For an existing in-flight row, `_decide_locked` skips `_record_decision`; `_review_payload` reconstructs recovery from the stored actor, decision, reason, and `final_action`. The end-to-end test changes the active policy version after a simulated post-resume failure and still recovers to `awaiting_outcome`, confirming that mutable policy output no longer strands the decision.

## CAS ownership prevents duplicate terminal completion and audit

```text
resume_pending --CAS--> resuming:<token>:<expiry> --awaiting_outcome--+
      ^                         |                                    |
      +------failure release---+                                    |
      +------expired CAS takeover                                    |
                                                                     v
                                                    CAS + audit --> completed
```

Concurrent claimants update against the complete expected status, so only one pending claim or stale-lease takeover succeeds. A non-owner either observes work in progress or returns the terminal row. Graph execution occurs after the claim transaction commits and with no retained ORM session, so concurrent incidents cannot exhaust the pool with owners waiting for nested persistence sessions.

Owner loss is fail-closed at completion: `_complete_resume` requires the exact lease token, and cleanup cannot replace a successor's different token. `completed` is written only after graph execution or reconciliation returns `awaiting_outcome`. That terminal CAS and `investigation_resumed` audit append share one transaction, so a failed owner cannot append the audit, rollback removes both changes, and a terminal retry does not append again.

**Likely, Medium:** fixed expiry does not prove the prior owner stopped. A graph call lasting beyond 900 seconds can continue after another worker claims the stale token; the terminal CAS still selects one winner and protects audit uniqueness, but both graph calls can write checkpoints and projections before owner loss is detected.
