# Development EDA Findings

Generated by `python -m evaluation.eda`. All fraud/cost findings use **train and validation labels
only**. Held-out test features are used only for the label-free traffic-rate calculation; test labels
remain outside the Phase 1–2 pipeline.

## Decision-driving findings

- The full 30,000-row feature stream averages **13.89 transactions/hour**.
- Development fraud-spike windows run at **2.28×–2.89×** normal volume and
  **13.72%–22.33%** observed fraud.
- Development benign surges run at an overlapping **2.30×–2.57×** volume but only
  **1.12%–2.19%** fraud.
- The train-reference promo flag share is **63.19%** within benign surge windows and **0%** in
  normal and fraud-spike windows. Across train+validation benign windows it is 60.92%.

Therefore volume is display context, not a trigger. Phase 2 triggers only on calibrated risk density
plus statistical persistence. Promotion context may raise the required lift, but cannot veto a
high-risk alert.
